# 팀 진행 현황과 다음 작업

기준일: 2026-10-21. 공개 저장소의 팀 인계용 상태이며, 담당·일정은 아래 제안을 팀이 합의한 뒤 확정한다. 과거 계획의 날짜는 역사적 기록이고 현재 마감으로 확인되지 않았다.

## 현재까지 확인한 범위

| 항목 | 상태와 해석 |
| --- | --- |
| 로컬 CPU MVP | POS 기반 RGB/영상 분석, 명시적 카메라 캡처, HR reference 평가, subject-disjoint HR-only 분류 baseline 구현 |
| 자동 테스트 | 알려진 통과 기준 98개. 합성 입력·계약·오류 처리 검증이며 실제 생체 성능 증거는 아님. PR마다 재실행 결과 기록 |
| 실제 파일 실행 | UBFC-rPPG DATASET_2 subject1: 1,547프레임 중 ROI 무효 384개, HR 출력 2/33창(6.1%), 나머지 31창 abstain |
| 동기화·정확도 | 영상/기준 시각 대응 미확인, reference 중복 시각 1개. 공식 정확도 평가 미실행; 측정된 정확도 없음 |
| 스트레스 분류 | 실제 labeled 데이터 학습·평가 미실행. HR 변화는 스트레스 점수가 아니며 UBFC-rPPG를 스트레스 정답으로 쓰지 않음 |
| 추가 데이터·학습 장비 | UBFC-Phys 원본 미확보. 후속 학습용 장비는 오프라인이며 설치·GPU·학습 검증은 이후 작업 |
| 카메라 | 사용자가 명시적으로 선택해 실행할 때만 접근. 실제 권한·장치 동작은 미검증 |

현재 ROI는 얼굴 하나를 검출한 뒤 이마/볼 사각형을 사용하는 proxy다. 6.1%는 창 수용률이며 정확도가 아니다. 품질 기준은 임시 휴리스틱이고, 창 수를 늘리기 위한 무근거 완화는 개선으로 인정하지 않는다. subject1은 첫 60초 calibration보다 짧아 delta HR 검증에도 사용할 수 없다.

## 처음 합류하면

1. [기여 안내](../CONTRIBUTING.md)에 따라 설치·doctor·테스트·합성 demo를 실행한다.
2. [사용법](USAGE.md)에서 CSV·시간·출력 계약을, [데이터 접근](DATA_ACCESS.md)에서 출처·이용 조건·실제 실행 한계를 확인한다.
3. 아래 한 작업을 Issue로 구체화해 범위·담당·수락 기준을 합의하고 작은 PR로 제출한다. 모든 역할은 **제안·미배정**이다.

## 우선순위 백로그

P0 두 작업은 독립적으로 시작할 수 있다. 추가 샘플의 파일 처리 점검은 동기화 조사와 병행할 수 있지만 정확도 비교는 동기화 완료가 선행한다.

| 우선순위 / 작업 | 의존성 | 완료 기준 | 소유 모듈 제안(미배정) |
| --- | --- | --- | --- |
| P0: ROI 안정성 | 접근 허용된 동일 입력, 현재 기준 결과 | 동일 프레임 범위·품질 기준으로 전후 ROI 무효 수, 유효 창 수/전체 수, 실패 이유 비교. no-face/다중 얼굴/공백 동작 회귀 테스트. 개선 여부와 남은 실패를 보고하고 근거 없이 기준을 낮추지 않음 | 영상 담당: `rppg/video.py`; 검증 담당: 관련 영상 테스트 |
| P0: 시간 동기화 조사 | 공식 문서·논문·허용된 원본 기준 파일 | 영상 시각과 센서 시각 대응, 중복 시각 처리, contact PPG→HR 산출 창/시각 규칙을 출처와 함께 고정. 원본 보존·변환 이력·단위 검증. 근거가 부족하면 평가 보류 사유 기록 | 평가 담당: `rppg/evaluation.py`, 관련 테스트; 데이터 담당: 변환 계약·manifest |
| P1: 추가 동의/이용 조건 확인 샘플 | 데이터 접근 권한·용량 확인; 정확도 평가는 위 동기화 완료 후 | 허용된 작은 샘플부터 해시·조건·동기화 상태·제외 이유 기록. 샘플별 ROI/창 coverage와 실패를 보고. 정렬이 입증된 경우만 pair 수·coverage·MAE/RMSE 보고. 피험자 간 일반화 주장은 별도 평가 필요 | 데이터·평가 담당: manifest와 평가 입력; 결과 공개 전 데이터 조건 점검 |
| P1: 사용자 선택 카메라 점검 | 사용자의 명시적 실행 선택·장치 권한 | 유한 duration으로 실행, 장치/권한 실패와 종료 시 release, RGB·보고서 출력 확인. 영상 원본 저장 없음 확인. 카메라 동작 성공과 생체 정확도 구분 | 캡처 담당: `rppg/video.py`, `rppg/__main__.py`, 관련 테스트 |
| P2: 후속 장비 설치·실데이터 baseline | 장비 온라인·환경/용량 확인, UBFC-Phys 접근·동기화·라벨 규칙 확정 | 잠금 설치·doctor·테스트 실제 결과 기록 후 작은 데이터로 시작. 피험자를 창 생성 전에 분리하고 Dummy 대비 HR-only baseline 평가. GPU/새 모델은 필요성 확인 후 별도 결정 | 환경 담당: `scripts/`, 의존성 파일; 학습 담당: `rppg/evaluation.py` |

역할 분담은 기능 소유와 별도 검증을 제안한다. 동일 파일을 동시에 바꿔야 하면 먼저 Issue에서 순서와 경계를 정하고, 기존 변경을 덮어쓰지 않는다. `rppg/signal.py`의 POS/품질 기준, `rppg/report.py`의 provenance/보고서는 영향 범위를 명시한 별도 검토 대상으로 둔다.

## 결과를 공유할 때

PR에는 입력의 공개 가능한 식별자·해시, 코드 revision, 명령·파라미터, 처리 범위, 전체/유효 프레임·창 수, abstention 이유, 실제 테스트 결과와 한계를 남긴다. 동기화 확인 전 MAE나 스트레스 성능을 게시하지 않는다. 원본 영상·생체 데이터·식별자·개인 경로가 담긴 보고서는 공개 GitHub에 올리지 않고, 권한을 확인한 집계와 합성 fixture로 재현한다.
